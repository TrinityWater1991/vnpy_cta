# 告警规则与通知

本文档定义 vnpy CTA 生产环境的告警分级体系、具体告警规则、通知渠道配置及静默规则。

## 告警等级定义

采用 P0-P3 四级告警体系，定义如下：

| 等级 | 标签 | 描述 | 响应要求 | 通知方式 |
|------|------|------|---------|---------|
| **P0** | critical | 系统不可用 / 资金风险 | 立即处理，15min 内响应 | 电话 + 即时消息 |
| **P1** | error | 核心功能受损 / 策略异常 | 30min 内响应 | 即时消息 |
| **P2** | warning | 功能降级 / 接近阈值 | 4h 内响应 | 即时消息（工作时段） |
| **P3** | info | 信息通知 / 日常报告 | 下一个工作日 | 日报 / 周报 |

## 告警规则列表

### P0 告警规则

| 规则名称 | 触发条件 | 持续时间 | 通知目标 | 备注 |
|---------|---------|---------|---------|------|
| 策略进程宕机 | 进程探活失败 | 0s | 值班组 + 电话 | 需立即拉起 |
| 行情网关断连 | 所有网关同时断开 | 5s | 值班组 + 电话 | 影响全部策略 |
| 交易网关断连 | 至少一个交易网关断开 | 5s | 值班组 | 单独网关不影响全部 |
| 资金异常变动 | 单笔 PnL > 总资金 × 5% | 0s | 值班组 + 电话 | 可能系统或人为失误 |
| 批量订单拒绝 | 1min 内拒绝订单数 > 5 | 0s | 值班组 | 检查账户或限价设置 |

### P1 告警规则

| 规则名称 | 触发条件 | 持续时间 | 通知目标 | 备注 |
|---------|---------|---------|---------|------|
| 高撤单率 | 撤单率 > 40% | 30s | 策略组 | 检查策略参数 |
| 订单 RTT 超标 | 订单 RTT > 500ms | 1min | 策略组 | 检查网络或交易所 |
| 行情延迟超标 | tick 延迟 > 200ms | 30s | 运维组 | 检查行情链路 |
| CPU 使用率超标 | CPU > 90% | 5min | 运维组 | 排查进程资源占用 |
| 内存使用率超标 | 内存 > 90% | 5min | 运维组 | 排查内存泄漏 |
| 磁盘使用率超标 | 磁盘 > 85% | 10min | 运维组 | 清理日志或扩容 |
| 策略连续亏损 | 策略连续 3 笔亏损 | — | 策略组 | 人工复核策略逻辑 |

### P2 告警规则

| 规则名称 | 触发条件 | 持续时间 | 通知目标 | 备注 |
|---------|---------|---------|---------|------|
| CPU 使用率偏高 | CPU > 70% | 15min | 运维组 | 预警 |
| 内存使用率偏高 | 内存 > 80% | 15min | 运维组 | 预警 |
| 回撤超出预警 | 当前回撤 > 8% | — | 风控组 | 接近止损线 |
| 资金使用率偏高 | 资金使用率 > 65% | — | 风控组 | 预警 |
| 持仓集中度偏高 | 持仓集中度 > 20% | — | 风控组 | 预警 |
| 策略低频交易 | 策略 2h 无任何交易 | 2h | 策略组 | 可能策略失效 |

### P3 告警规则

| 规则名称 | 触发条件 | 通知目标 | 备注 |
|---------|---------|---------|------|
| 每日 PnL 报告 | 收盘后生成 | 全体 | 日报 |
| 策略周报 | 每周五收盘后生成 | 策略组 | 周报 |
| 系统健康报告 | 每日凌晨生成 | 运维组 | 巡检报告 |

## 通知渠道配置

### 渠道定义

| 渠道 | 协议 | 适用范围 | 限流策略 |
|------|------|---------|---------|
| 钉钉 (DingTalk) | Webhook + 自定义机器人 | 值班组、策略组 | 每分钟最多 20 条 |
| 企业微信 (WeChat) | 群机器人 Webhook | 全体通知 | 每分钟最多 20 条 |
| 电话 (Phone) | 语音通知（通过云厂商 API） | P0 告警 | 每 10min 最多 1 次 |
| 邮件 (Email) | SMTP | 日报 / 周报 | 每小时最多 10 封 |

### 钉钉机器人配置

```yaml
dingtalk:
  webhook_url: "https://oapi.dingtalk.com/robot/send?access_token=xxx"
  secret: "加签密钥"
  msg_type: "markdown"   # 支持 text / markdown
  at_mobiles:            # P0/P1 告警 @ 指定人
    - "13800138000"
  at_all: false          # 仅在 P0 时 @all
```

### 企业微信机器人配置

```yaml
wechat_work:
  webhook_url: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"
  msg_type: "markdown"
```

## 静默规则

### 非交易时段静默

CTA 策略仅在特定时段运行，非交易时段应抑制不必要的告警。

| 时段 | 说明 | 静默规则 |
|------|------|---------|
| 交易日 08:55 - 15:30 | 日盘交易时段 | 全部告警开启 |
| 交易日 20:55 - 23:00/02:30 | 夜盘交易时段（依品种） | 全部告警开启 |
| 交易日 15:30 - 20:55 | 日盘收盘到夜盘开盘 | P2/P3 静默，P0/P1 保留 |
| 夜盘收盘 - 次日 08:55 | 收盘到次日开盘 | P1/P2/P3 静默，仅 P0 保留 |
| 非交易日（周末/节假日） | 全天 | 仅 P0 保留 |
| 策略维护窗口 | 通知的维护时间段 | 全部静默 |

### Alertmanager 静默示例

```yaml
# Prometheus Alertmanager 静默配置示例
silences:
  - # 非交易时段静默 P2/P3
    matchers:
      - severity =~ "warning|info"
      - schedule =~ "off_hours"
    comment: "非交易时段自动静默 P2/P3 告警"
    # 通过 cron 创建/删除静默，或使用 Alertmanager API
```

## 值班与升级

| 级别 | 值班角色 | 响应时间 | 升级路径 |
|------|---------|---------|---------|
| 一线 | 运维工程师 | 15min (P0) / 30min (P1) | -> 二线 |
| 二线 | CTA 策略负责人 | 30min (P0) / 1h (P1) | -> 技术负责人 |
| 三线 | 技术负责人 / 架构师 | 1h (P0) | 最终决策 |
