# 持仓对账

> 本页定义 CTA 系统持仓记录与经纪商（期货公司）柜台持仓的核对流程，确保账实一致。

## 对账时机

| 场景 | 对账频率 | 优先级 | 说明 |
|------|----------|--------|------|
| 每日盘前 | 每日一次 | 高 | 开盘前必须完成 |
| 每日盘后 | 每日一次 | 高 | 收到结算单后执行 |
| 系统重启后 | 每次重启 | 最高 | 参见 [[startup-shutdown]] |
| 异常断连恢复 | 每次重连 | 高 | CTP 重连后立即核对 |
| 收到结算单后 | 每日 | 中 | 与期货公司结算单逐笔核对 |
| 人工干预后 | 每次操作 | 最高 | 参见 [[order-management]] |

## 对账数据源

| 数据源 | 内容 | 获取方式 | 可靠性 |
|--------|------|----------|--------|
| vnpy 本地数据库 | 系统持仓记录 | `select * from position_data;` | 依赖日志完整性 |
| CTP 柜台查询 | 交易所持仓 | `reqQryInvestorPosition()` | 权威数据源 |
| 期货公司结算单 | 日终结算持仓 | 结算文件 / 邮件 | 最终依据 |
| 交易日志 | 成交流水 | `journalctl -u vnpy-cta` | 辅助核查 |

## 对账流程

### 步骤一：数据采集

```bash
# 1. 导出系统持仓
$ python scripts/export_positions.py --output /tmp/system_positions.csv

# 2. 查询柜台持仓（通过 vnpy API 或 CTP 查询工具）
# 3. 获取结算单（如为盘后对账）
```

### 步骤二：字段比对

| 比对字段 | 系统数据 | 柜台数据 | 匹配条件 |
|----------|----------|----------|----------|
| 合约代码 | rb2410 | rb2410 | 完全一致 |
| 持仓方向 | Long / Short | Long / Short | 完全一致 |
| 持仓手数 | 10 | 10 | 完全一致 |
| 昨持仓 | 5 | 5 | 完全一致 |
| 今持仓 | 5 | 5 | 完全一致 |
| 持仓均价 | 3,580 | 3,580 | 偏差 < 0.5 个 tick |
| 浮动盈亏 | +2,000 | +2,000 | 偏差 < 1 元 |

### 步骤三：差异判定

| 差异类型 | 可能原因 | 处理方案 |
|----------|----------|----------|
| 手数不一致 | 漏单 / 重复成交 / 撤单未同步 | 逐笔核查成交记录 → 手工修正 |
| 方向不一致 | 信号反向 / 数据错误 | 紧急复查策略逻辑 → 按柜台数据调整 |
| 均价偏差 | 部分成交 / 手续费差异 | 计算加权均价 → 修正系统记录 |
| 浮动盈亏偏差 | 行情缓存差异 | 刷新行情后重新计算 |

## 差异处理

### 轻微偏差（手数一致，均价偏差 < 1 tick）

```bash
# 修正系统均价记录
$ python scripts/sync_position.py --contract rb2410 --price 3580
```

### 严重偏差（手数不一致）

1. 立即暂停相关策略交易（参见 [[../risk-management/controls]]）
2. 导出当日完整成交流水
3. 逐笔比对成交记录与柜台成交回报
4. 确定差异根因
5. 手动修正持仓记录
6. 恢复策略运行

## 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 柜台查不到持仓 | 查询接口调用时机不对 | 在结算完成后查询 |
| 双向持仓 | 股指 / 商品锁仓未合并 | 按交易所规则合并计算 |
| 昨仓今仓混淆 | T+1 结算规则差异 | 区分昨仓 / 今仓分别比对 |
| 浮动盈亏计算差异 | 行情缓存价格不同 | 统一行情源后重算 |
