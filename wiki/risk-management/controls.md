# 风控框架

> 本页描述 vnpy_cta 的三层风控体系：盘前（策略级）、盘中（引擎级实时）、盘后（盘后分析）。

## 总体架构

系统采用三层递进式风控架构：

```
┌─────────────────────────────────────────────────────┐
│  第一层：盘前风控（策略级）                            │
│  → 策略参数校验、账户资金检查、持仓限额预检             │
├─────────────────────────────────────────────────────┤
│  第二层：盘中风控（引擎级实时）                         │
│  → 订单频率限制、撤单率监控、资金占用实时检查           │
├─────────────────────────────────────────────────────┤
│  第三层：盘后风控（分析级）                            │
│  → 交易统计复盘、异常行为识别、风控参数调优             │
└─────────────────────────────────────────────────────┘
```

## 第一层：盘前风控（Pre-Trade / Strategy-Level）

在策略初始化及启动前执行，阻断不符合条件的策略启动。

| 检查项 | 说明 | 触发动作 |
|--------|------|----------|
| 策略参数校验 | 验证参数范围、类型合法性 | 启动失败，日志记录 |
| 账户权益检查 | 确认账户可用资金 ≥ 策略最低资金要求 | 禁止启动，通知运维 |
| 持仓上限预检 | 当前持仓 + 策略计划持仓 ≤ 产品持仓上限 | 调整仓位或拒绝启动 |
| 合约状态检查 | 合约是否可交易、非停牌、非到期 | 跳过该合约，告警提示 |
| 历史表现校验 | 策略在最近 N 天内的表现是否达标 | 准入控制（可选） |

## 第二层：盘中风控（In-Trade / Engine-Level Real-Time）

CTA 引擎在运行期间实时执行的风控检查，是核心防线。

### 实时风控检查项

| 检查项 | 周期 | 阈值/规则 | 触发动作 |
|--------|------|-----------|----------|
| 订单频率限制 | 每笔订单 | ≤ N 笔/秒 | 延迟或拒绝下单 |
| 撤单率监控 | 每分钟 | 撤单率 ≤ M% | 暂停交易 X 分钟 |
| 资金占用检查 | 每次下单 | 占用资金 ≤ 账户权益 × P% | 拒绝下单 |
| 持仓集中度 | 每次下单 | 单品种 ≤ Q% | 拒绝下单 |
| 自成交防护 | 每笔订单 | 买卖双向同合约同价格 | 拦截订单 |
| 涨跌停检查 | 每笔订单 | 价格不超出涨跌停价 | 调整价格或拒绝 |
| 连续亏损监控 | 每日 | 连续亏损天数 ≥ K | 自动降仓或暂停 |
| 策略运行超时 | 实时 | 策略计算耗时 > T ms | 告警并进入保护模式 |

## 第三层：盘后风控（Post-Trade / After-Hours Analysis）

收盘后执行的分析与复盘任务。

| 分析项 | 频率 | 说明 |
|--------|------|------|
| 交易执行质量分析 | 每日 | 滑点统计、成交率、撤单原因分布 |
| 风控事件统计 | 每日 | 统计当日触发的风控规则及次数 |
| 策略绩效归因 | 每周 | 盈亏归因分析 |
| 敞口风险评估 | 每日 | 隔夜敞口、品种相关性风险 |
| 风控参数复审 | 每月 | 审查风控参数是否需调整 |
