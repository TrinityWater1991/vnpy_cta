# 策略生命周期

本文档定义 vnpy CTA 策略从开发到退役的标准生命周期流程。每个阶段均设有明确的 **gate criteria（关卡条件）**，未达标不得进入下一阶段。

## 生命周期总览

```
开发(dev) → 回测(backtest) → 模拟交易(paper) → 小资金实盘(live_small) → 全仓实盘(live_full) → 退役(retired)
```

各阶段核心目标与产出物如下表所示。

| 阶段 | 状态标识 | 核心目标 | 预期时长 | 关键产出物 |
|------|---------|---------|---------|-----------|
| 开发 | dev | 策略逻辑实现与单元测试 | TODO | 策略代码、单元测试报告 |
| 回测 | backtest | 历史数据验证策略有效性 | TODO | 回测报告、参数组合 |
| 模拟交易 | paper | 实时行情下验证逻辑稳定性 | TODO | 模拟交易日志、绩效曲线 |
| 小资金实盘 | live_small | 最小风险验证实盘表现 | TODO | 实盘绩效、滑点评估 |
| 全仓实盘 | live_full | 按目标仓位运行 | 持续 | 日常监控报告 |
| 退役 | retired | 停止运行并归档 | — | 归档文档、最终绩效总结 |

## 阶段切换流程

1. **发起申请**：策略负责人填写状态转移申请表，附上对应 gate criteria 的验证材料。
2. **评审**：CTA 策略评审会议（频率：TODO）对申请进行评审。
3. **审批**：评审通过后由 TODO（角色）签字确认。
4. **执行**：运维团队执行状态切换，更新 [[catalog]] 中的策略状态。
5. **记录**：在 [[catalog#历史状态变更记录]] 中登记变更记录。
